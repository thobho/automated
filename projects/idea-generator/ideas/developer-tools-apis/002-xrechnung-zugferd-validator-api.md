# 002 — XRechnung/ZUGFeRD validator and generator API (swap-in for rejected I062)
**One-liner:** A hosted REST API (plus Docker image) that validates and generates German E-Rechnung files (XRechnung, ZUGFeRD/Factur-X) for small ERP vendors, Excel/Word-invoice users' tooling and agencies, wrapping the KoSIT validator and Mustang with batch mode, plain-language error fixes and a DATEV hand-off.
**Field:** developer-tools-apis | **Type:** API
**Target customer:** Small German and DACH software vendors, freelancers and agencies that add E-Rechnung to their own invoicing/ERP tools; the developer or product owner pays. Count: not found for software vendors (unverified). Demand base: every German business must receive e-invoices since 1 Jan 2025 and issue them from 2027/2028 (count of firms not sourced here).
**Problem:** Developers and small vendors must emit valid XRechnung/ZUGFeRD and prove it against KoSIT rules before the issuing duty starts. Free validators exist but are web forms or run-it-yourself Java; hosted APIs are young.
**MVP scope (≤6 weeks):** (1) `POST /validate` (XML or PDF/A-3 with embedded XML) running KoSIT and EN 16931 rules, returning structured errors with fix hints in German and English. (2) `POST /generate` from JSON to XRechnung CII/UBL and ZUGFeRD PDF/A-3. (3) Batch endpoint and API keys with metered usage (Stripe). (4) Docker image for self-hosting under a licence. (5) CI example (GitHub Action). Tests: public sample files and KoSIT test suites run automatically.
**Why now:** German issuing duty from 1 Jan 2027 for larger businesses and 1 Jan 2028 for the rest, receiving already since 1 Jan 2025 (IHK Magdeburg; PwC newsletter on the BMF letter). A guide source states an 800,000 EUR prior-year turnover threshold; that figure is only in one guide and was not checked against the statute (unverified).
**Foreign analogues:** The market itself is German, so the analogues are direct rivals: RechnungsAPI.de (Capterra listing, 0 reviews); finaX E-Rechnung API on AWS Marketplace (self-hosted); a Frankfurt-hosted PDF/A-3 API sold through a WordPress plugin at 0.10 EUR per invoice (100 for 10 EUR); an Apify actor at 4.00 USD per 1,000 validations with 2 total users and 1 monthly user. None shows public revenue (unverified). The strongest "money" proof is adjacent: kostenlose-erechnung.de sells invoicing with a validator at 9.92 EUR/month (119 EUR/year) and 19.08 EUR/month (229 EUR/year).
**Competition (PL / global):** Free: KoSIT validator (192 stars, Apache-2.0), Mustang (488 stars, Apache-2.0), phive (Peppol/XRechnung engine, 77 stars), federal-state web validators (L8-F18), kostenlose-erechnung.de validator (3 checks/month free). Paid and young: the API vendors above and at least 8 "Show HN" single-developer E-Rechnung tools in 2026, each 1–3 points (L6-F16). Polish market: no relevant Polish demand (this is a German-market play). Gap: batch + CI + fix hints + DATEV hand-off; none verified as missing, so the gap is weak.
**Evidence of pain:** No direct complaint found about existing validator APIs. Only supply-side evidence: dozens of new tools (HN list, GitHub libraries) and Google-suggest queries "xrechnung viewer kostenlos", "zugferd prüfen online kostenlos" (L8-F18), which show demand but a strong expectation of free. Trend data not checked (Google Trends not accessible): unverified.
**Monetization:** Usage-based API: 0.01–0.05 EUR per validated/generated invoice with a monthly minimum of 19–49 EUR, plus a self-hosted licence at a few hundred EUR/year (estimate, set between the 0.004 USD Apify price and the 0.10 EUR plugin price). Payer: the vendor or agency.
**Revenue sketch (estimate):** Assumptions: 29 EUR average plan (about 125 PLN). 6 months: 8 customers = about 1,000 PLN MRR. 12 months: 25 customers = about 3,100 PLN MRR, 10,000 PLN MRR needs about 80 customers on the 29 EUR plan, which looks hard against free tools.
**First 10 customers:** German-language SEO ("E-Rechnung API", "XRechnung validieren API"), listing on GitHub Marketplace and AWS Marketplace, cold email to small German ERP/shop-plugin vendors listed on WordPress/Shopify marketplaces. German-language support is a cost.
**Build complexity:** low (glue around maintained Java libraries on the founder's stack, L7-F21). Risks: rules and CIUS profiles change twice a year (KoSIT releases), keeping validation current is an ongoing duty, wrong validation results can cause legal exposure for customers (disclaimer needed).
**Pros / Cons / Risks:** Pros: fast, testable build, dated demand trigger, usage billing. Cons: free official tools and young rivals, low willingness to pay for validation alone, German-market SEO and support in a foreign language, no Polish moat. Risks: German deadline may slip (a trade body asked to postpone 2027, per search summary in L5-F04), commoditization by ERP vendors.
**Scores (1–5):** L1 2, L2 1, L3 2, L4 2, L5 4, L6 2, L7 5, L8 2, L9 2 | **Weighted:** 2.4 / 5 | **Chance band:** <5% (scored down from the shortlist's 3.0 after research found free validators, hosted APIs and no complaints; L3 or L6 not 1, so no knock-out)
**Cheapest validation test (≤1 week, ≤200 PLN):** Landing page with an interactive "paste XML, get fixes" demo wrapping KoSIT and a 29 EUR/month waitlist button; post to German developer communities (Reddit r/de_EDV style forums, Xing/LinkedIn groups of ERP vendors) and email 30 small German invoicing/plugin vendors. Success: 5 vendors reply with a concrete integration plan, 2 would pay.
**Kill criteria:** Fewer than 3 vendors out of 30 contacted reply with a real need; or all repliers already run Mustang/KoSIT in-house; or the German issuing date is postponed beyond 2028.
**Confidence:** low
**Devil's advocate:** The write-up already scored this 2.4, and a second search removes the remaining gap. Its differentiators were batch + CI + plain-language fix hints + generation. Found in this review: Factora offers one-call generation of KoSIT-checked XRechnung/ZUGFeRD from 49 EUR/month with 250 invoices and a free sandbox (GetApp listing, from a search summary; page returned 403, so unverified); normbill offers a hosted generate/validate/parse API with validation "Free within fair use" and a free tier (PHP client v0.1.1 published 2026-07-17, [packagist](https://packagist.org/packages/normbill/xrechnung)); Rechnungslotse runs a hosted MCP server plus REST API that returns every KoSIT/EN 16931 violation with rule ID and plain-text explanation and a per-rule fix database (directory listing on [mcpservers.org](https://mcpservers.org/servers/xkallex/rechnungslotse-mcp), 403 to the fetcher, content from search summary, unverified); XInvoice ships a PHP client for a similar API ([packagist](https://packagist.org/packages/ventnet/xinvoice-client)). With free official validators, free-tier hosted ones, 8+ HN launches and ERP vendors building it in, validation is a commodity priced at zero, and generation is sold by German-speaking vendors closer to the customer. The founder would sell in German, to German developers, with no Polish moat and ~10 h/week. The trigger is real: the 800,000 EUR prior-year turnover threshold for the 2027 issuing duty is confirmed by several guides (e.g. [Grant Thornton](https://www.grantthornton.de/themen/2026/e-rechnungspflicht-2027-die-wichtigsten-fragen-und-antworten-zur-e-rechnung/), § 27 Abs. 38 UStG; statute text not opened), but it benefits the incumbents as much as a newcomer.
