# Developer-side pain and crowding: e-invoicing, KSeF, Peppol

Lens 6 findings from GitHub, Hacker News and Stack Overflow, via their public APIs. All sources accessed 2026-10-29. These show where developers are stuck **and** how many other developers are already building the fix, which is counter-evidence for lens 2. IDs `L6-Fnn` are stable anchors.

### L6-F14 — The official KSeF PDF-visualisation library is a repeated developer complaint (26 and 15 comments)
- **Evidence:** repo https://github.com/CIRFMF/ksef-pdf-generator (81 stars, 20 open issues, created 2025-10-31). Issue #84 "Wersja produkcyjna, publikacja do NPM" (26 comments, open since 2026-03-25): "klienci często wymagają formy PDF... skoro mogą wyświetlić PDF na oficjalnej stronie" https://github.com/CIRFMF/ksef-pdf-generator/issues/84 ; issue #25 (15 comments, closed, 2026-01-13): "Kiedy to repozytorium zostanie zaaktualizowane do stanu chociaż przypominającego produkt dla ludzi a nie wersje demo?" with questions why previews are not part of the C# and Java libraries https://github.com/CIRFMF/ksef-pdf-generator/issues/25 .
- **Reading:** integrators want a production-grade KSeF XML → PDF (visualisation) service/library in their language. The ministry ships a TypeScript demo. A hosted API or Java/Python/Node library is the obvious fill; official libraries (C#, Java clients) exist but not the renderer.
- **Counter-evidence:** the ministry can ship a proper version any time (the gap is a snapshot); willingness to pay is unknown for a library whose competitors are free.
- **Repeated or one-off:** repeated across three issues; developers, not end buyers.
- **Product category:** KSeF PDF rendering API / Docker image; see [L2-F09](../02-weak-competition/dev-tools-and-polish-apis.md#l2-f09--ceidg-and-krs-company-data-api-clients-small-old-some-are-scrapers) for the registry-API analogue.
- **Confidence:** medium.

### L6-F15 — "Ask HN: How are you preparing for PEPPOL?" — 67 points, 76 comments; cost of an access point and "my bookkeeping software will handle it" both appear
- **Evidence:** https://news.ycombinator.com/item?id=42777669 (2025-01-21; read via the HN Algolia API). The poster notes Peppol access is not free and direct access needs technical audits. A SaaS owner for freelancers/SMEs replies that running your own access point costs "a basic yearly fee of 2000 euros" before anything else (answer cut in the API snippet). Other replies: "I'm using bookkeeping software that has already integrated it... no extra charge on my paid plan"; "Stripe app in their marketplace for sending invoices over PEPPOL"; a Norwegian B2B-software maker had to add EHF support because the government mandated it.
- **Reading:** Peppol is a real compliance topic for small SaaS owners, but the common answer is "my accounting vendor will add it". Pain is strongest for people who **build invoicing software**, not for end users.
- **Counter-evidence:** several commenters dispute that the EU forces Peppol (only Belgium and Italy cited); Germany's route is XRechnung/ZUGFeRD.
- **Repeated or one-off:** one high-traffic thread; 2025-01, so 21 months old (outside the 2-year window by a margin of 3 months only).
- **Confidence:** medium.

### L6-F16 — Counter-evidence: at least 8 "Show HN" e-invoice tools in 2026 each got 1–3 points
- **Evidence (HN Algolia, stories since Nov 2024):** RechnungNova, XRechnung and ZUGFeRD for German businesses (2 pts, 2026-05-03) https://news.ycombinator.com/item?id=47997355 ; E-Rechnung Push for German small businesses (1 pt, 2026-02-20) https://news.ycombinator.com/item?id=47094304 ; Convert Word/Excel/PDF invoices to XRechnung (1 pt, 2026-01-24) https://news.ycombinator.com/item?id=46747868 ; Thelawin, EU e-invoices from JSON (1 pt, 2026-04-26) https://news.ycombinator.com/item?id=47909874 ; Eleata, validate Peppol/XRechnung/Factur-X in CI (2 pts, 2026-05-25) https://news.ycombinator.com/item?id=48263771 ; Billoop, Factur-X/UBL from Shopify orders (2 pts, 2026-05-15) https://news.ycombinator.com/item?id=48150502 ; send a Peppol e-invoice in 5 minutes (2 pts, 2026-04-29) https://news.ycombinator.com/item?id=47951671 ; Smart Tax and E-Invoicing Software (1 pt, 2025-07-15) https://news.ycombinator.com/item?id=44568236 .
- **Reading:** a flood of single-developer tools targeting the German E-Rechnung gap, each with almost no discussion. HN is not the buyers' venue, so low points do not prove no demand, but they prove **supply crowding**: the "German E-Rechnung validator/generator API" seed ([L5 seed 2](../05-why-now/README.md#seeds)) will meet at least these eight small rivals plus established vendors.
- **Confidence:** high on the list, medium on interpretation.

### L6-F17 — Counter-evidence: GitHub shows 709 new KSeF repos in 2025 and 542 in 2026 so far; free libraries already cover ZUGFeRD/XRechnung
- **Evidence:** GitHub search API, 2026-10-29: repositories matching "ksef" created in 2025: 709; created since 2026-01-01: 542 (the matching is loose, it includes forks and unrelated names, so treat as an upper bound). Issues mentioning KSeF created in the last 90 days: 580 across GitHub. Popular KSeF clients: https://github.com/CIRFMF/ksef-client-csharp (115 stars), https://github.com/N1ebieski/ksef-php-client (92), https://github.com/stacking-hq/ksef2 (82, Python, pushed 2026-10-28), https://github.com/CIRFMF/ksef-client-java (49). For ZUGFeRD/XRechnung/Factur-X: https://github.com/ZUGFeRD/mustangproject (488 stars, 149 open issues, Java), https://github.com/horstoeko/zugferd (441), https://github.com/stephanstapel/ZUGFeRD-csharp (395), https://github.com/gflohr/e-invoice-eu (367), https://github.com/akretion/factur-x (314, Python).
- **Stack Overflow signal:** question counts for the tags/terms (Stack Exchange API total): KSeF 1, XRechnung 20, ZUGFeRD 48, Factur-X 19, Peppol 43. Polish developers evidently ask on GitHub and in Polish communities, not on Stack Overflow.
- **Reading:** generic "KSeF client library" or "ZUGFeRD generator" ideas are heavily served by free open source. Pain remains in the glue: PDF rendering (F14), delegated access, change notification (L6-F06), validation with plain-language fixes.
- **Confidence:** medium (counts from a search API; loose match).

### L6-F18 — OpenLinker, a free self-hosted BaseLinker alternative started in Dec 2025, shows seller-side tool fatigue (51 stars, 227 open issues)
- **Evidence:** https://github.com/openlinker-project/openlinker (created 2025-12-09, status alpha; README: "SaaS channel managers (you pay forever and your data lives on their servers) or custom scripts"; it links a "vs BaseLinker" page). Open issues 227 is the API's count (includes PRs).
- **Reading:** open-source projects appearing to replace BaseLinker is a quiet signal of price pain (compare [L2-F01](../02-weak-competition/allegro-and-ecommerce-tools.md) for the Base price rise), and also competition against any paid Allegro order hub seed. The stars are low, so it is not yet a market force.
- **Confidence:** low-medium.
